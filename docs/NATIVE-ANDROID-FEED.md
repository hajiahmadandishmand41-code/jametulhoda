# فید بومی اندروید جامعه‌الهدی

مسیر فید عمومی و فقط‌خواندنی:

`GET https://jametulhoda.vercel.app/api/mobile-feed`

این API فقط رکوردهای منتشرشدهٔ وب‌سایت را برمی‌گرداند. هیچ اتصال به شبکه‌های اجتماعی، جمع‌آوری پست خارجی، SDK شخص ثالث یا متغیر محیطی اجتماعی در قرارداد این فید وجود ندارد.

## قرارداد پاسخ

پاسخ موفق، JSON با ساختار کلی زیر دارد:

```json
{
  "ok": true,
  "items": [],
  "meta": {
    "count": 0,
    "refreshed_at": "ISO-8601 timestamp"
  }
}
```

هر عضو `items` شامل شناسه، نوع محتوا، عنوان، خلاصه، متن، نویسنده، تاریخ، پیوند منبع و نشانی تصویر در صورت وجود است. فهرست فقط محتوای عمومی منتشرشده را شامل می‌شود؛ اطلاعات حساب، داده‌های کاربران و اطلاعات مدیریتی در این مسیر برگردانده نمی‌شود.

## محدودیت‌های فعلی

- روش‌های مجاز: `GET` و `HEAD`. درخواست دیگر با پاسخ `405` رد می‌شود.
- تعداد آیتم‌های درخواستی محدود می‌شود؛ پاسخ، فهرست همهٔ دیتابیس نیست.
- فید عمومی فقط‌خواندنی است و هیچ عملیات حساب یا مدیریتی را از طریق آن انجام نمی‌دهد.
- فید فعلی فهرستی محدود از محتوا می‌دهد؛ صفحه‌بندی کامل و جست‌وجوی سراسری باید در API و کلاینت جداگانه آزمون شود.
- لایک در سایت فعلی API و جدول امن ندارد؛ کلاینت نباید شمارندهٔ جعلی یا لایک محلی را به‌عنوان لایک سروری نشان بدهد.

## بررسی

پس از هر تغییر، گردش‌کار **PHP syntax check** را بررسی کنید. پاسخ واقعی Production باید از نظر کد HTTP، نوع محتوا، ساختار JSON و نبود رکوردهای پیش‌نویس آزمایش شود. وضعیت CI به‌تنهایی جایگزین آزمون زندهٔ API نیست.


## API حساب کاربری بومی

مسیر جداگانهٔ احراز هویت: `/api/mobile-auth`. این API از جدول موجود `users` و اعتبارسنجی‌های `includes/identity.php` استفاده می‌کند و حساب یا پایگاه‌دادهٔ موازی نمی‌سازد.

- `POST /api/mobile-auth` با `{"action":"login","identifier":"...","password":"..."}` برای ورود.
- `POST /api/mobile-auth` با `{"action":"register","full_name":"...","country":"AF","phone":"...","email":"","password":"...","password_confirm":"...","agreed_terms":true}` برای ساخت حساب عمومی. نقش همیشه `user` است و از بدنهٔ درخواست خوانده نمی‌شود.
- `GET /api/mobile-auth` با سرآیند `Authorization: Bearer <token>` برای دریافت حساب فعلی.
- `POST /api/mobile-auth` با سرآیند Bearer و `{"action":"update_profile","full_name":"...","email":"..."}` برای تغییر نام و ایمیل.
- `POST /api/mobile-auth` با سرآیند Bearer و `{"action":"change_password","current_password":"...","new_password":"...","password_confirm":"..."}` برای تغییر رمز.
- `POST /api/mobile-auth` با سرآیند Bearer و `{"action":"logout"}` برای باطل کردن توکن جاری.

توکن خام فقط یک بار به کلاینت برگردانده می‌شود؛ دیتابیس SHA-256 آن را نگه می‌دارد. اعتبار توکن هنگام هر درخواست با فعال بودن کاربر و `auth_version` دوباره بررسی می‌شود و عمر آن ۳۰ روز است. تغییر رمز، نسخهٔ احراز هویت را بالا می‌برد و همهٔ توکن‌های قبلی را باطل می‌کند. این API هیچ قابلیت پنل مدیریت را در اختیار اپلیکیشن قرار نمی‌دهد.

**پیش از انتشار عمومی:** این مسیر باید در محیط staging با همان درایور واقعی دیتابیس آزمون یکپارچه شود؛ بررسی syntax یا سبز بودن CI به‌تنهایی اثبات‌کنندهٔ صحت ورود، ثبت‌نام یا ابطال توکن در Production نیست. لایک تا زمانی که مدل داده و endpoint تراکنشی/یکتا برای آن طراحی و آزموده نشده باشد، در اپلیکیشن فعال نشود.
